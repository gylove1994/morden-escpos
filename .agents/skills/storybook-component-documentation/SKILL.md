# Storybook - Component Documentation (Tellus repo conventions)

Component documentation for `@workspace/ui` is entirely **auto-generated by autodocs**, with all prose coming from **JSDoc comments**. This repo maintains no MDX docs pages and never uses `parameters.docs.description` — do not introduce either.

## Documentation mechanisms (these three only)

### 1. Component description = JSDoc above `meta`

```tsx
/**
 * Display additional information or actions to an input or textarea.
 */
const meta = {
  title: "ui/radix/InputGroup",
  component: InputGroup,
  tags: ["autodocs"], // generates the Docs page
  parameters: {
    layout: "centered",
  },
} satisfies Meta<typeof InputGroup>;
```

- Every component's meta must carry `tags: ["autodocs"]` and a concise JSDoc description (one or two sentences stating the component's purpose).
- Interaction regression stories use `tags: ["!dev", "!autodocs"]` to stay out of the docs page (see storybook-story-writing).

### 2. Story description = JSDoc above the story export

```tsx
/**
 * Input groups with icon addons for visual enhancement.
 */
export const WithIcons: Story = {
  render: (args) => (/* ... */),
};
```

- Every story that appears on the docs page should have a one-line JSDoc explaining what the variant demonstrates.
- Describe behavior and purpose, not implementation details.

### 3. Props documentation = JSDoc in component source

Autodocs extracts the prop table from TypeScript types and JSDoc:

```tsx
interface OnceSecretDialogProps {
  /** Dialog title, provided by the caller (no built-in copy). */
  title: string;
  /**
   * The one-time secret to display in a read-only monospace field.
   */
  secret: string;
  /** Accessible label for the copy button before copying. */
  copyAriaLabel: string;
}
```

- Write concrete meaning in JSDoc; avoid tautologies like "The title".
- Annotate defaults with `@default` — but note that `ui/patterns/*` components **must not** have default values containing user-visible copy (see below).

## Documentation red lines for pattern components (`docs/spec/prd01-ui-storybook.md`, A.1)

- Component source (including JSDoc example code) **must not** contain user-visible copy; example copy appears only in `*.stories.tsx` args.
- Prop JSDoc should state the "copy is injected by the caller" contract, e.g. the behavior when required copy is missing (enforced by TypeScript, or the node is not rendered).
- The ui package carries no i18n strings; English copy on docs pages is example-only.

## Patterns we do NOT use (avoid introducing)

- ❌ `parameters.docs.description.component` / `.story` — this repo uses JSDoc consistently (`addon-docs` extracts it).
- ❌ `.mdx` docs pages and `@storybook/blocks` (`Canvas` / `ColorPalette` / `Typeset`, etc.) — there are currently no MDX files, and design-token showcases already exist as dedicated stories (`color` / `typography` / `spacing` / `shadow`, etc.).
- ❌ Verbose hand-written `argTypes` documentation — existing stories mostly have an empty `argTypes: {}`; prop info is extracted automatically from TypeScript types + JSDoc. Only write argTypes when a custom control is needed.

## Verification

```bash
pnpm --filter @workspace/ui build-storybook   # docs pages must build
pnpm spellcheck                                # fix real cSpell typos (most other hits are false positives)
```

Or open locally with `pnpm --filter @workspace/ui storybook` and confirm the Docs page description, prop table, and examples render correctly.
